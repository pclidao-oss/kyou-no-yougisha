# 今日の容疑者

20人の住人の証言から全員を「無実」「犯人」に確定する、日本語の日替わり推理ゲーム。4列×5行、毎日JST午前0時に同じ問題を選びます。架空の町、人物、事件で、名称・画面・文章はオリジナルです。

## ローカル起動

Node.js 22以上（SQLite統合テストはNode.js 24推奨）。追加パッケージ不要。

```sh
node scripts/generate.mjs
node --test tests/*.test.mjs
node scripts/build.mjs
node scripts/serve.mjs
```

`http://127.0.0.1:8913/yougisha/` を開く。環境変数 `PORT` で変更可能。今回の確認用プレビューは8914番。集計APIはローカルプレビューでは503を返し、準備中と表示する。

未来日のQAはlocalhost限定で `?date=2026-10-18&preview=1`。一般公開画面は今日以前の問題のみ選択できる。公開JSONの未来問題を技術的に隠す設計ではない。

## 仕組み

### 判定と証言

20ビットの犯人集合を扱う。最初に公開される1人の状態と、確定済み住人の証言だけで全候補を列挙する。その住人の状態が残る全候補で一致したときだけ判定が通る。犯人数6〜10は生成ルールであり、プレイヤーへ追加証言として暗黙に渡さない。答えと一致しただけでは通らない。

ブラウザーのWeb Workerで候補を保持・絞り込むため、判定中も画面を止めない。正解の `sealed` は日付由来のキーによるXOR＋Base64。これは難読化であり秘密保護ではない。判定処理はsealedを読まない。名前の頭文字は重複せず五十音順、7職業を各2〜3人に割り当てる。

隣・行・列・間・職業・四隅・外周・方向・同じ立場・最大行・偶奇の候補を正解から作る。候補から1人を確定できる証言を選び、難しい日は名前で指定した3人の人数制約や同じ立場の証言を組み合わせる区間を挟む。最後までソルバーで追跡して検証する。手がかりの表記テストは定型文・未定義値・句点・構造の検証であり、自然さの完全な保証ではない。

### 曜日別の難しさ

各公開段階で、単独の証言では確定しないが全証言の組み合わせで確定する住人の数を数える。

|曜日|組み合わせで確定する住人の目標| 
|---|---:|
|月|0|
|火|3|
|水|4|
|木|6|
|金|8|
|土|12|
|日|16|

同時に、証言総数・確定可能住人が1人だけになる段階の数・全員までの段階数も記録する。現在は組み合わせ人数を主な受け入れ基準にしている。実際の人の難しさ・所要時間を保証しない。最後に2件の補足証言が出る場合がある。

### 保存・結果

localStorageの読み書きはtry/catch。進行は合法な判定の順で復元する。ミス・ヒント・使用した住人・読了証言・初回クリア・平均タイム・曜日別ベストを端末に保存。タイムは捜査開始からの経過時間で、タブを閉じた時間も含む。連続日数は今日か昨日を起点にクリア日を連続で数える。別端末や保存の消去で引き継がれない。

最初のヒントは有効な証言を光らせ、2回目は確定可能な住人を光らせる。カードは記号と文字でも状態を示す。結果は4列×5行の絵文字、時間、ミス・ヒント回数。X/LINEは共有画面へ移動するだけで自動投稿しない。

## 無料での公開・既存ゲームへの追加

既存の百科事典リポジトリはPrivateで未解読本文を含む。Publicへ変更したり、新ゲームの公開リポジトリへコピーしない。

本プロジェクトだけを公開リポジトリに置く。`.github/workflows/daily.yml` はPublicリポジトリのみ実行。毎日23:10 JSTに当日から30日先までを生成し、全問題のテスト後に問題ファイルだけをコミット。検証済みの静的ファイルを2日保持のartifactにする。

ゲームはPublicリポジトリのraw JSONから最新の作り置きを読むため、毎日のPages再配備は不要。GitHubへの接続が失敗すると、Pages内の31問へフォールバックする。GitHubでの生成が止まっても最後の作り置きで30日先まで遊べる。GitHubが長期ダウンした場合はPages内の静的問題がある2026-11-12までとなる。画面そのものを直す場合はPagesへ別途配備する。

`node scripts/integrate.mjs <既存Pagesのソースコピー>` で `site/yougisha` と、既存トップのフッターリンク1つを追加。既存 `_worker.js` と `_routes.json` は変更せず、静的配信できない設定なら停止する。新ゲームだけは独自のCSPをHTML metaで指定し、X-Frame-Options: DENYを付ける。既存ゲームのCSPは維持。配備前に公開16ファイルが最新ソースと一致することを確認し、既存ゲームの33テストを通した。

全国集計の `server/api.js` とD1の `server/schema.sql` は独立。公開時は `/yougisha/api/summary`、`/yougisha/api/event`、`/yougisha/stats` を新APIに配線する。`DB` binding、ランダムな `METRICS_SALT` と `STATS_KEY`、`METRICS_ENABLED=true` が必要。秘密値はSecretに入れ、公開JSON・リポジトリ・URL共有に入れない。管理画面は数字のHTMLを表示し、`/yougisha/api/stats` はJSONを返す。Authorization Bearerにも対応。管理URLのkeyは第三者へ共有しない。

承認後に使うPages用の具体的なルートは `server/pages-worker.js` と `server/pages-routes.json` に用意した。Pages binding名は `YOUGISHA_DB`、Secretsは `YOUGISHA_METRICS_SALT` / `YOUGISHA_STATS_KEY`、変数は `YOUGISHA_METRICS_ENABLED`。本番はこのラッパーと新ルートを含む。既存 `/api/*` は従来のGAMEへ転送し、新ゲーム用だけを専用D1へ接続する。

最終確認: 新ゲーム16テスト、既存ゲーム34テストが成功。本番55ファイルが保存したソースと一致。今日の問題を本番の390px幅で20人まで判定し結果コピーが成功。既存ゲームは第197問を読み込み、語句入力が有効。Public Actionsの最終実行も成功: https://github.com/pclidao-oss/kyou-no-yougisha/actions/runs/38275100535 。

公開前に `node scripts/check-free.mjs` でCloudflare契約を読む。未確認・有料契約・不完全な一覧なら停止。既存の百科事典側 `freeAccount()` は有料契約を許容するので、本ゲームの無料確認には使わない。Pagesの静的配信とWorkers/D1の従量利用は区別する。既存の有料契約のダウングレードは他作品へ影響するため行わない。

## 全国集計と計測

端末内のランダムIDを、サーバー側のsalt付きSHA-256で変換して保存。名前・メール・IP・入力した言葉はアプリDBへ保存しない。匿名端末数であり実人数ではない。端末IDを削除・別端末利用すると別集計になる。

開始は端末×問題日で1回、クリアは最初の時間だけ、共有は操作回数（端末×問題日100回まで）。全国平均と上位%は申告タイムの集計。同タイムを含め、速いほうから自分以下の秒数の割合を求める。改ざん防止の大会順位ではない。7日再訪は初参加日からちょうど7日後にイベントがあった端末の比率で、8日後以降では代替しない。

1日5000イベントをDBのカウンターで受け付ける補助上限あり。DB読み取りや拒否時のアクセスまで無料にする仕組みではなく、Paidアカウントで追加費用を完全に防ぐ上限ではない。APIは同一Originのみ受け付け、集計の失敗はプレイを止めない。ゲーム内と共有プライバシーポリシーに計測説明を追加済み。

## Actionが止まったときの直し方

1. 公開リポジトリのActions → Daily puzzle stock → 最新実行を開き、赤いステップを確認。
2. GitHubのスケジュール遅延・長期無更新による停止なら、workflowをEnableしてRun workflow。
3. Tests失敗ならその日付をローカル生成し、ソルバーと文面を直す。既存問題の正解は書き換えない。
4. botのpushが拒否されたらActionsのcontents:write権限と対象ブランチ保護を確認。保護を黙って解除しない。
5. 成功後、最新コミットに30日先のJSONがあるか、配備経路が公開へ反映したか両方確認。
6. 予備が尽きても前日の問題を「今日」と偽らない。「捜査記録が届いていません」と表示して更新する。

## 埋め込み版の共通集計（2026-10-21）

`node scripts/build-embedded.mjs` で `dist-embedded` を作り、その中身をZIP化する。ZIP直下はindex.html。1.1.0以降は無料ゲームnet（file.game16.net）とitch.io（html-classic.itch.zone）から公式の `/yougisha/api/embed/event` と `/summary` に通信する。Cookie・管理キーは送らない。GPCを尊重し、通信失敗でもローカルのゲームを続ける。

受信側は配信元を完全一致のOriginで限定し、event/summary以外のCORSやAuthorizationヘッダーを許可しない。配信元に応じたchannelをサーバー側で割り当て、ブラウザ・訪問のハッシュも掲載版別に分離する。元の公式IDは変更しない。Originによる分類は不正なイベント送信を完全に防ぐ認証ではなく、匿名集計は目安である。

管理室の「どの掲載版で遊ばれたか」は公式・無料ゲームnet埋め込み・itch.io埋め込みを分ける。「どこから来たか」は参照元区分で別の指標。未受信は0人ではなく、ファイル未更新や通信制限の可能性を示す。全国集計・お題別・7日再訪は対応版への差し替え後から埋め込みも合算し、掲載版をまたぐ同一人物の重複は除けない。

受信側の公開だけでは掲載済みZIPは更新されない。先方サーバーのZIP差し替え、またはitch.ioの既存アップロード更新と公開動作の確認が必要。過去の埋め込み利用数を補完しない。リリース識別はZIP内のrelease.json。
